Build an agentic AI system for data analysis

An agent is a language model in a loop: it chooses an action, a tool runs it, and the result goes back to the model until the job is done. This guide builds one that analyzes your CSV files, in about 100 lines of Python.

1. The idea 2. Set up 3. Define tools 4. Write the loop 5. System prompt 6. Guardrails 7. Test it 8. Put it online 9. Automate it 10. Glossary

1. The idea

A normal chatbot answers once. An agent keeps going. Step through a sample run below to see the loop: the model decides, a tool acts, and the result returns to the model.

Model decides
Tool runs
Result returns

Everything else in this guide supports that loop: tools give the model abilities, the system prompt gives it habits, and guardrails keep it safe and affordable.

2. Set up

You need Python 3.10+, a CSV file, and an Anthropic API key from console.anthropic.com. Create a folder, a virtual environment, and install the packages.

Windows PowerShell
mkdir agent; cd agent
python -m venv venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
venv\Scripts\Activate.ps1
pip install anthropic pandas numpy matplotlib scipy statsmodels
$env:ANTHROPIC_API_KEY="your-key-here"
Mac / Linux
mkdir agent && cd agent
python3 -m venv venv
source venv/bin/activate
pip install anthropic pandas numpy matplotlib scipy statsmodels
export ANTHROPIC_API_KEY="your-key-here"
Never put your API key inside a file you will upload to GitHub. Keep it in an environment variable.

3. Define tools

Tools are the agent's hands. Start with two. Clear names and descriptions matter more than anything else here, because the model reads them to decide what to call.

ToolWhat it does
inspect_dataLoads the CSV into df and reports shape, column types, missing values, and the first rows, so the model never guesses column names.
run_pythonRuns code in a namespace that persists between calls, so later steps build on earlier ones. Errors return as text and the model usually fixes its own bug.

Each entry in TOOLS has three fields: name (the label the model uses to ask for it), description (plain English the model reads to decide when to use it), and input_schema (the arguments it takes). Inside the schema, "properties": {"path": {"type": "string"}} means "one argument called path, and it is text," while "required": ["path"] says the model must supply it.

The model never runs anything itself. It replies with a request such as {"name": "run_python", "input": {"code": "print(1)"}}, your code runs the matching function with **input (which turns the dictionary into named arguments), and you send the output back as a tool result.

data_analysis_agent.py (part 1)
import contextlib, io, sys, traceback
import anthropic, pandas as pd, numpy as np

client = anthropic.Anthropic()
MODEL = "claude-sonnet-4-6"
MAX_STEPS = 20
MAX_CHARS = 4000
NAMESPACE = {"pd": pd, "np": np}

TOOLS = [
  {"name": "inspect_data",
   "description": "Load a CSV into `df`; return shape, dtypes, missing counts, head.",
   "input_schema": {"type": "object",
     "properties": {"path": {"type": "string"}}, "required": ["path"]}},
  {"name": "run_python",
   "description": "Run Python with persistent state (pd, np, df). Use print().",
   "input_schema": {"type": "object",
     "properties": {"code": {"type": "string"}}, "required": ["code"]}},
]

def trunc(s):
    return s if len(s) <= MAX_CHARS else s[:MAX_CHARS] + "\n...[truncated]"

def inspect_data(path):
    df = pd.read_csv(path)
    NAMESPACE["df"] = df
    return trunc(f"shape: {df.shape}\n{df.dtypes}\n{df.isna().sum()}\n{df.head().to_string()}")

def run_python(code):
    buf = io.StringIO()
    try:
        with contextlib.redirect_stdout(buf):
            exec(code, NAMESPACE)
    except Exception:
        return trunc(buf.getvalue() + traceback.format_exc())
    return trunc(buf.getvalue()) or "(no output; use print())"
Running model-written code with exec is risky on a machine you care about. Use Google Colab, a container, or run it in the browser (see step 8).

4. Write the loop

This is the whole agent. Send the conversation, run any tool the model asks for, append the results, and repeat. Stop when the model answers without requesting a tool, or when you hit the step limit.

data_analysis_agent.py (part 2)
def run_tool(name, args):
    # Dispatcher: pick the Python function matching the tool name
    if name == "inspect_data":
        return inspect_data(**args)
    if name == "run_python":
        return run_python(**args)
    return f"Unknown tool: {name}"   # the model reads this and can correct itself

def analyze(path, question):
    messages = [{"role": "user",
                 "content": f"Dataset: {path}\nQuestion: {question}"}]
    for step in range(MAX_STEPS):
        resp = client.messages.create(
            model=MODEL, max_tokens=4000,
            system=SYSTEM_PROMPT, tools=TOOLS, messages=messages)
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")

        results = []
        for b in resp.content:
            if b.type == "tool_use":
                print(f"[step {step+1}] {b.name}")
                results.append({"type": "tool_result",
                                "tool_use_id": b.id,
                                "content": run_tool(b.name, b.input)})
        messages.append({"role": "user", "content": results})
    return "Stopped: step limit reached."

if __name__ == "__main__":
    print(analyze(sys.argv[1], sys.argv[2]))

Run it with python data_analysis_agent.py data.csv "Which variables best predict price?" and watch the step trail print as it works.

5. System prompt

The system prompt sets the agent's habits. For data analysis, the most valuable instructions are the ones a careful statistician would follow anyway. Define SYSTEM_PROMPT above analyze.

SYSTEM_PROMPT = """You are a careful data analyst working in Python.
1. Call inspect_data first. Never guess column names or types.
2. Check missing values, duplicates and outliers before modeling.
3. Use run_python for all computation. The dataset is `df`.
   Print concise summaries, never whole tables.
4. Report effect sizes and uncertainty, not just p-values.
   Distinguish association from causation.
5. If the data cannot support a conclusion, say so plainly.
6. Finish with a short answer: findings, key numbers, assumptions, caveats."""

6. Guardrails

Agents act on their own, so set limits before you share one.

  • Step cap. MAX_STEPS stops runaway loops and runaway bills.
  • Output truncation. One huge printed table can flood the model's context window.
  • Sandboxing. Execute code somewhere disposable, with no network access and no private files.
  • Spending limit. Set a monthly cap in the Anthropic Console.
  • Human approval. If you later add tools that send email or modify data, require a confirmation first.
  • Untrusted content. Text inside a dataset or web page can contain instructions. Treat tool output as data, never as commands.

7. Test it

You cannot improve what you cannot measure. Build a small test set before tuning anything.

  1. Collect 10 to 20 questions on datasets where you already know the right answer.
  2. Plant problems in a few: duplicate rows, a wild outlier, a column that leaks the answer.
  3. Run the agent on all of them and record how often it is correct and how often it notices the planted problem.
  4. Read the step trails of the failures. Usually the fix is a clearer tool description or one more line in the system prompt.
  5. Re-run the full set after every change so you know the change helped.

8. Put it online

GitHub Pages only hosts static files and cannot keep an API key secret, so the safe pattern has three parts:

  • A web page on GitHub Pages holds the interface and runs the loop in the browser.
  • Pyodide (Python compiled to WebAssembly) runs the run_python tool in the visitor's browser, so their data never leaves their computer and nothing needs sandboxing on your side.
  • A Google Apps Script proxy stores your API key, checks an access code, enforces a daily call cap, and forwards each request to the Anthropic API.

Whatever you deploy, set the spending limit first, keep the daily cap low while testing, and share the access code privately.

9. Automate it

Once started, the loop already runs by itself. What is left to automate is the setup and the starting. Three small steps cover it.

One-click launcher. A .bat file is a text file of Windows commands that run in order when you double-click it. Save this as run.bat in your agent folder (it uses activate.bat, which avoids the PowerShell permission error):

@echo off
cd /d %~dp0
if not exist venv python -m venv venv
call venv\Scripts\activate.bat
pip install -q anthropic pandas numpy matplotlib scipy statsmodels
python run_all.py

Store your API key permanently once, then open a new terminal: setx ANTHROPIC_API_KEY "your-key-here"

Batch runner. Save as run_all.py. It analyzes every CSV in an inbox folder, writes a report to reports, and skips files already done:

import glob, os
from data_analysis_agent import analyze

os.makedirs("reports", exist_ok=True)
for path in glob.glob("inbox/*.csv"):
    out = f"reports/{os.path.splitext(os.path.basename(path))[0]}.md"
    if os.path.exists(out):
        continue
    report = analyze(path, "Check data quality, then report the most important patterns.")
    open(out, "w", encoding="utf-8").write(report)

Schedule it. Windows Task Scheduler can run the launcher daily (the computer must be on and logged in):

schtasks /create /tn "DataAgent" /tr "C:\path\to\agent\run.bat" /sc daily /st 07:00
Unattended runs still spend API credit and execute model-written code. Keep the spending limit and step cap in place, only feed it files you trust, and read the first several reports before relying on them.

10. Glossary

TermMeaning
JSONA plain-text format for structured data: objects { } of key-value pairs, arrays [ ], strings, numbers, true/false, and null. Tool definitions and all API traffic use it. Python dictionaries and lists map directly onto it.
f-stringA string starting with f where {value} is replaced by that value: f"Dataset: {path}". Use f"""...""" for several lines. Literal braces must be doubled: {{.
**argsUnpacks a dictionary into named arguments, so f(**{"code": "x"}) equals f(code="x").
Type hintsOptional notes like name: str and -> str. Python ignores them when running, so you can leave them out.
Trailing commaA comma after the last item in a list or dictionary. Python allows it; strict JSON does not.
Virtual environmentA private copy of Python for one project (python -m venv venv), so its packages stay separate from everything else.
.bat fileA Windows text file of commands that runs when you double-click it.
